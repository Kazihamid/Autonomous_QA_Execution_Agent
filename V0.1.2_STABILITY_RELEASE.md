# Autonomous QA Execution Agent v0.1.2 Stability Release

## Implemented
- Recorder now captures semantic locators plus CSS/XPath structural fallbacks.
- Scenario IR validation blocks locator-required actions that have no supported locator.
- Scenario Repository shows user-friendly locator/runtime errors.
- Run executes generated Playwright + Pytest through the local runner.
- Runner injects BASE_URL and recorded non-secret parameters at runtime.
- Secrets are never generated into source code; local Docker runner reads them from `.env.runtime`.
- Exported `.env.example` includes the selected Base URL and blank runtime variable placeholders.
- Generated Python + Playwright and Java + Selenium test values are read from environment variables.
- Application management: Edit, Archive, protected Delete.
- Environment management: Edit, Enable/Disable, protected Delete.
- Delete operations are blocked when dependent automation history exists.

## Local runtime secrets
Copy `.env.runtime.example` to `.env.runtime` and populate only the variables required by your scenarios. Never commit `.env.runtime`.

Example:
```env
SECRET_PASSWORD=your-local-test-password
```

Restart the runner after changing runtime secrets:
```powershell
docker compose up -d --force-recreate runner
```

## Existing recordings
Scenarios recorded before v0.1.2 may contain weak or missing locator metadata. Re-record affected steps/scenarios to benefit from the new locator capture logic.
